# Contributing to the RAI Framework

Thanks for considering a contribution. This framework gets better when practitioners share what they've learned.

## What We're Looking For

**High-value contributions:**
- New worked examples from real domains (healthcare, HR, education, fintech, etc.)
- Improvements to templates based on real-world usage
- Additional compliance mappings (CCPA, sector-specific regulations, non-US frameworks)
- Translations
- Corrections (factual errors, broken links, outdated regulatory references)

**Also welcome:**
- Glossary additions
- Clarity improvements (if something confused you, it'll confuse others)
- Tool integrations (CI checks, linters, automation around the templates)

**Not looking for:**
- Vendor-specific product placements
- Theoretical additions without practical guidance
- Changes that make the framework longer without making it more useful

## How to Contribute

### Small Changes (typos, link fixes, clarifications)

1. Fork the repo
2. Make your change
3. Open a PR with a one-line description

### Larger Changes (new templates, examples, sections)

1. **Open an issue first** describing what you want to add and why
2. Wait for a thumbs-up before investing time
3. Fork, write, PR

This avoids wasted effort if the change doesn't fit the framework's direction.

### New Worked Examples

These are especially valuable. If you've applied the framework (or similar governance) to a real AI system, consider writing it up:

1. Use the existing examples as a structural guide (`examples/` directory)
2. Include: context, risk classification walkthrough, key artifacts (summarized), monitoring approach, lessons learned
3. Anonymize as needed - real patterns matter more than real company names
4. Focus on **what you learned**, not just what you did

## Quality Bar

Every contribution should:
- [ ] Be **actionable** - tell people what to DO, not just what to think about
- [ ] Be **concise** - if it can be said in fewer words, say it in fewer words
- [ ] **Scale with risk** - don't add process that applies to everything equally
- [ ] Include **examples** where possible
- [ ] Not duplicate what's already covered

## Style Guide

- Use plain language. Avoid jargon where a simpler word works.
- Use tables for structured information. They're scannable.
- Use checklists (- [ ]) for action items. They're completable.
- Mark required risk tiers: "(Required for 🟡 High and 🔴 Critical)"
- Link to other framework sections and templates when referencing them.
- Templates should be fill-in-the-blank with example values in italics.
